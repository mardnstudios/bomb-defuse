2. Information the game handles

Game profile and local storage

The game stores a player profile on the device using browser local storage (including inside the Android WebView). Depending on play, the profile can include a display name and avatar, account mode/provider and Firebase user identifier, account email when signed in, coins, upgrades and power inventory, campaign unlocks and stars, scores, play statistics, achievements, daily challenge and goal progress, preferences, and privacy choices.

Guest progress is stored locally unless you sign in and synchronize it. Local data remains on the device until you use Reset Progress, delete browser/app data, or otherwise remove it from the device.

Sign-in and account information

Optional account sign-in is provided through Firebase Authentication. The code supports email/password, Google, and Facebook sign-in. Depending on the method and the information made available by the provider, Firebase may process an account UID, email address, display name, and provider account details. Firebase Authentication also maintains the sign-in session in the browser or app. Email/password credentials are submitted to Firebase Authentication; the game does not put the password into its saved profile or Firestore game snapshot. Google and Meta may separately process information under their own policies when you choose those sign-in methods.

Cloud saves

When an authenticated account is online, the game synchronizes a profile snapshot with Cloud Firestore in the Firebase project. The document is addressed using the Firebase UID and includes the profile/game-progress fields described above, including account email and identifier, progress, statistics, preferences, and consent fields. Firestore may also process service and connection information needed to provide and secure cloud storage. The game does not send the password in the cloud-save document.

3. Optional Firebase Analytics

Analytics is off by default for new profiles. The Analytics SDK is loaded and collection is enabled only after both stored Analytics consent values are explicitly on. Turning Analytics off blocks further game events, disables collection, and discards pending custom events in the current session. Missing or conflicting consent values are treated as off.

When enabled, the game may send these allowlisted gameplay events: level started, completed, or failed; power used; and a bomb-generation result. Event parameters are limited to predefined level and puzzle categories, duration, stars, power type, difficulty, wire/phase counts, and rule category. The game does not attach the full player profile, account email, Firebase UID, free-text answers, or puzzle solutions to these custom events.

Firebase Analytics may also collect automatically generated app-usage and technical information, such as app/device identifiers, app version, device/operating-system details, interaction or session information, and network-derived information, as described by Google. The game does not describe this data as anonymous. Analytics consent is separate from Crash Diagnostics and AdMob/UMP choices.

Choice: In the game, open Account Settings → Privacy & Data → Analytics. Collection remains off unless both consent fields are on. You can turn it off there at any time.

4. Optional crash diagnostics

Crash Diagnostics is off by default and is separate from Analytics. It uses one fail-closed consent setting for browser JavaScript reporting and native Android Crashlytics. Missing or inconsistent consent values remain off.

Website and Android WebView — Sentry

After opt-in, the Sentry Browser SDK can report uncaught JavaScript errors raised in the page and unhandled promise rejections. Error-object promise rejections are captured only when their stack points to first-party game code; non-error rejection values are replaced with a generic message. The game filters reports: it removes user identity, request data, extra/log-entry fields, tags, breadcrumbs, cookies, headers, bodies, URL query parameters, and stack-frame variables. It keeps the exception type and a sanitized stack (source filename without query/hash and line/column numbers) plus limited browser, operating-system, or app-version context. Sentry and the network connection may also process technical delivery information such as an IP address. Error reporting is not represented as anonymous.

Native Android crashes — Firebase Crashlytics

On Android, Crashlytics is used for native crashes; the game does not deliberately forward the same JavaScript exceptions to Crashlytics. Crash reports can include stack traces, exception class/message, app version, crash time, device/operating-system characteristics, and installation/session identifiers as described by Firebase. The game does not set a Crashlytics user ID or attach the saved player profile.

Android Crashlytics collection defaults to off. Enabling or disabling native collection takes effect on the next app launch; opt-out also asks the plugin to delete unsent reports where supported. Because the native SDK’s setting is next-launch, turning the setting off cannot be described as an instantaneous stop for native crashes in the already-running process. Sentry’s browser capture is blocked immediately on opt-out.

Choice: Account Settings → Privacy & Data → Crash Diagnostics. It does not follow from enabling Analytics or accepting an ad message. You can also request help through the privacy contact above.

5. AdMob and Google UMP

The browser website does not load the native AdMob module. The current Android debug build is configured for Google test ads only; it uses Google’s sample test banner and interstitial units, not live ad-unit IDs. The Android release asset set does not contain the debug test-enablement marker, so this test integration does not request ads from the release build.

In an eligible Android debug build, Google’s User Messaging Platform (UMP) requests consent information at launch and may show a Google privacy/consent form. The game initializes the ads SDK and requests a test ad only if UMP reports canRequestAds. If consent status is unknown, the UMP request fails, or eligibility is false, the game withholds ad requests. The in-game legacy “Personalized Ads” preference is not itself UMP consent and does not authorize an ad request.

Google’s UMP and Mobile Ads services may process ad-request and technical information such as app/device identifiers, IP/network details, and ad delivery or fraud-prevention information, subject to the applicable choices and Google’s policies. Google test ads are used in development; no production ad-unit IDs are configured by this policy’s code snapshot.

Choices: Follow the Google UMP form when it appears. If UMP says an in-app privacy-options entry point is required, use Account Settings → Privacy & Data → Manage Ad Privacy Options. Google’s Ad Settings can also manage Google ad-personalization choices, but it does not replace the app’s UMP flow.

6. Service providers and sharing

Information is transmitted to the selected service provider when you use its feature: Google/Firebase for sign-in, cloud saves, Analytics (if opted in), Crashlytics (if opted in on Android), and UMP/AdMob test-ad requests in eligible Android debug builds; Sentry for crash reports after Crash Diagnostics opt-in; and Meta when you select Facebook sign-in. These providers process information under their own terms and privacy notices. The app does not intentionally sell player profile data, but this policy does not characterize all provider processing as anonymous or as a sale/non-sale under every jurisdiction’s legal definitions.

7. Storage, retention, and deletion

  • Local game profile: stored on the device/browser until reset, app/browser data is removed, or the user otherwise deletes it.
  • Cloud save: the game does not currently configure an automatic Firestore expiration or a separate retention schedule. A cloud document may remain until it is deleted in the Firebase project.
  • Provider diagnostics and analytics: Google/Firebase and Sentry apply their own service retention and deletion processes. The game does not configure a separate retention period for those provider records. See the provider links above for current details.

Export, reset, and account deletion

The in-game Export My Data action downloads a JSON export of selected account display information, game statistics, personal bests, achievements, economy, daily progress, and privacy preferences. Reset Progress resets the local game profile; it should not be treated as a request to erase a cloud account record.

For a signed-in account, Delete Account first deletes the Firestore document at users/{authenticated Firebase UID}—the only user-owned Firestore document path currently used by the game—and then requests deletion of that Firebase Authentication account. Local profile data is reset only after both remote operations succeed. If Firestore deletion fails, the account and local data remain. If Firebase Authentication rejects deletion (for example, because a recent sign-in is required), the game attempts to restore the saved cloud snapshot under the same authenticated UID; local data remains, and the screen reports that deletion did not finish so you can retry after signing in again. If restoration also fails, the game reports that the cloud document may remain deleted, keeps local data, and permits a retry. Guest account deletion resets only the local profile.

Only the root users/{uid} document is identified by the current cloud-save code; the game does not use user-owned Firestore subcollections in this implementation. Cloud deletion depends on Firebase Console Firestore Security Rules permitting an authenticated user to delete only the document whose ID matches their own UID. Do not send passwords or authentication tokens in a support request.

No app-specific retention period has been set for cloud saves or provider reports. Complete a retention and deletion process appropriate to your launch regions before publication.

8. Security and children

The game uses HTTPS-based third-party services when hosted or connected, but no online service or local device can be guaranteed completely secure. Do not include passwords, private messages, or other sensitive information in a display name or support request.

Age/children’s privacy: the project code does not establish a publisher age rating or a child-directed privacy program. The game is intended for users who are 15 years of age or older. We do not knowingly collect or solicit personal information from children under the age of 15. If you are under 15, please do not play the game or submit any personal information through display names or support requests. If we learn that we have collected personal data from a child under 15 without verifiable parental consent, we will take steps to delete that information promptly.
